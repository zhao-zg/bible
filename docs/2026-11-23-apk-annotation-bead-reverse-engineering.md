## 一、结论速览

1. **权威实现"更精确"的根源不是算法更聪明，而是把两类信息做成了数据**：
   - 注解内"哪里可以点击"→ 预存的字符区间表（`footnote_all_link_10`，20,401 行）；
   - 标记锚点位置 → 预存的字符偏移（`note_loc` / `loc`，插入式渲染，原文零污染）。
   运行时几乎不做"从散文里猜引用"这件事——猜的那部分（span 文本 → 定位码）只发生在**白名单文本内部**。
2. **章号/节号字符集天然分离**是引用识别不歧义的关键：章号一律中文数字（一、十、一○四），节号一律阿拉伯数字（6、15、22）。`"西二9，一15～19"` 中 `9` 必是节、`一15` 必是新章。这一文法从 35,941 条非空引用串中 100% 可解析，越界率 0.014%。
3. **我们的 `resource/zh_rcv.db` 与权威 APK 数据库是同一数据集**：footnote 16,664/16,664 行、bead 26,283/26,283 行在 `(书, 章, 节, unit/flag, loc, seq)` 键上 **100% 对齐**。权威库独有的 `footnote_all_link_10` 可以直接按这套键 join 进我们的管线，无需重新标注。
4. 我们现在运行时的 `ref-detector.js` 推断方案：覆盖 span 事实约 **74.6%**，且注解全文词法解析比 span 事实多产出 **14%** 的"合法格式引用"——多出部分是叙述性文字里的数字/段落号被误识别。这正是点击误导/错链的来源。

## 三、偏移语义三条铁律（数据 + 反编译双重验证）

1. **经文内标记锚点 `loc` 是 1-based 插入位**：渲染时把标记字符串插到 0-based 索引 `loc-1` 处（即标记出现在第 loc 个字符之前）。
   反编译证据（`ScheduleBottomSheet.java` L499-559）：把 `loc` 收集后，按 `if (loc - 1 == i13)` 建稀疏标记数组，插入时 `text.substring(0, i19+i20) + 标记 + text.substring(i19+i20)`，`i20` 补偿此前已插入标记的长度。
   → 我们 `export_bible_sql_json.py: apply_markers()` 的 1-based 逐位插入与它**完全同语义**，此点无需修改。
2. **同位置多标记直接拼接成一个上标串**：`note_num` 与 `beaded` 同 loc 时合并显示（反编译 L540-543：相等 loc 的连续条目字符串相加）。节号≥10 时不用阿拉伯数字上标，而用重复的 `poem_foot` 符号（"˙"）表示计数，字母用 `super_script_char` 上标字符。
3. **注解内引经区间 = 「该节该 unit 下所有注解串联文本」的 `[start_loc-1 : end_loc)`**（start 1-based、end 0-based 排他），覆盖引用正文本身、不含两侧括号。
   坐标空间不是单条注文，而是同一 (书,章,节,unit) 下**全部注解按注号顺序首尾相接**的整段字符流——这是阶段一落地时的关键发现（原文按单注切分会错位，且有 51% 的 span 文本字段为空、只有偏移）。
   例：创 1:1 注1 `[54:66]` → `'弗一10，三9，提前一4下'`；注2 从串联位 937 开始，`[987:989]` → 注2 内 `'26節'`。
   ⚠ 实测该区间与当前 `note_content` 存在**累积漂移**（11,392 个可精确定位的 span 中完全精确仅 202 个；漂移量随注解内引用个数递增 +1~+8）。原因：区间按旧版文本计算，注解文本后来加了全角括号/句点而未重算。权威 App 仍按原区间渲染 `QuoteClickableSpan`——因为区间足够宽（整段括号内容），体验上仍可点中。**这给我们的启示：区间不能盲信，导入时应以区间文本回查正文位置。**

## 四、渲染管线（反编译还原）

```
读一章
 ├─ SELECT 全部该章 footnote 行 + bead 行（ORDER BY id）
 ├─ 每节(unit)组装：把 note_num / beaded 字符串按 loc-1 插入正文
 │    （记录插入后位置 footNoteIndex；同 loc 拼接）
 ├─ ListViewAdapter.getView：
 │    SuperscriptSpan + MyClickableSpan 套在上标标记上（数字转 superscript_number 上标字体）
 │    └─ 点击 → FootNoteFragment（注解列表）
 ├─ FootNoteAdapter（注解列表渲染）：
 │    · note_content 按 ˍ 切段，段间 \n\n（changeLineIndex）
 │    · 每行加编号前缀；对每个 link span 设
 │      QuoteClickableSpan[linkStart+前缀, linkEnd+前缀]（换算跨行偏移）
 │    └─ 点击 span → 以“当前节的 书/章”为上下文解析 span 文本 → QuoteActivity
 ├─ BeadAdapter（串珠列表）：每个 beaded_content 拆成单条引用
 │    └─ 点击 → QuoteActivity 显示被引经文（QuoteFragment 直接渲染经文+注锚）
 └─ 引用文本 → 定位码：AbbrHelper（书卷缩写匹配，最长优先；约 vs 约壹/约贰/约参 显式特判）
      + MyTool.toNumber（中文数字→int：十进制逐位 + 十/百复合）
```

关键类清单（`jadx_full/sources/ted/android/bibleread/`）：
`read/ScheduleBottomSheet`（内容+标记组装）、`read/ListViewAdapter`（上标/点击渲染）、
`read/FootNoteAdapter`（注解渲染 + `QuoteClickableSpan`）、`read/abbr/AbbrHelper`（书卷识别）、
`tool/MyTool`（中文数字、上标字符转换）、`tool/SQLHelper`（全部 SQL）、`read/QuoteActivity/QuoteFragment`（引经展示）。

## 六、精度测量（本次全量实验）

| 实验 | 输入 | 结果 |
|---|---|---|
| 引用串全量解析 | 46,684 条（含 10,737 空串、6 条串珠互指如`见6a`） | 35,941 条有效串 **100% 产出引用**；展开 73,388 条，越界仅 10 条（**0.014%**），越界均为 `見N註M` 这类指向"注解"而非经节的固有歧义 |
| span 事实 | 9,692 个有效引经 span（另有 10,709 空占位行） | 解出 15,427 条有效引用（区间内解析，零散文误报） |
| 注解全文词法解析（模拟我们现在的做法） | 同 16,664 条注解正文 | 17,654 条"合法格式"引用，**多出 14%**（叙述文字里的段落号/编号/上标数字被误识） |
| 括号受限解析（我们 ref-detector 主体策略） | 同上 | 覆盖 span 事实 **74.6%**（其余 25.4% 的权威可点引用不在成对括号内，或形态特殊） |

**结论**：把"哪里可点"从运行时推断改为数据（span），可同时消除 14% 误报和 25% 漏报。

## 七、与我们现状的差距对照

| 维度 | 权威 APK | 我们（现状） | 差距 |
|---|---|---|---|
| 经文标记锚点 | DB 预存 loc，渲染时插入，原文纯净 | 导出期内嵌 `{N}[a]` 字面标记进 content | 我们的标记污染正文（搜索/复制/搜索高亮都会带上 `{1}[a]`），且与权威 loc 同数据源，无精度差 |

### 11.1 落地过程中修正的三个认知

| 发现 | 影响 |
|---|---|
| **loc 是「该节该 unit 下所有注解串联」后的全局坐标**，不是单条注文内的坐标 | 按单注切分会导致后续注全部错位；必须按串联空间换算回单注 |
| `footnote_all_link_10` 中 **10,709 行（52%）的 `note` 文本为空**，但偏移仍有效 | 这些 span 在 APK 里同样可点；丢失它们会少一半引用。已按偏移回填切片文本（q4） |
| `seq`（注号）在同一节同一 unit 内**不唯一**（如创 1:2 两行 note_num=2） | 必须用 `footnote._id` 关联注文，否则切片会串到另一条注 |
| 源表存在 **169 条**重复/嵌套区间（同区间重复登记，或短区间完全落在长区间内） | 按区间去重 + 包含归并（保留长区间），避免嵌套可点区 |

### 11.2 重定位策略（四级 + 括号吸附）

1. **q0 文本锚定**：繁→简（从 big5/gb 双份注解逐字对照学到 1,094 组映射）+ 去标点后，在注文中检索区间文本；
2. **q2 数字归一形状匹配**：把数字（阿拉伯与中文）折叠为 `#` 再匹配，解决 `45，47` vs `四十五，四十七`、`7～25节` vs `7～15节` 这类版本差异；
3. **q1 漂移估算**：用同组已锚定 span 在串联空间的漂移量外推；
4. **q3 原始偏移**：按原偏移换算（未验证）；
5. **q4 文本回填**：源文本为空时，用上述坐标取切片作为区间文本，并做"像引用"的可用性校验（含数字/书卷缩写/中文数字，否则丢弃）；
6. 最后统一 **括号吸附**：切片内若有未闭合的开括号，改取该括号内的内容；再去掉外层括号与尾随 `。，、；`。

## 14. 对齐权威实现的「三元组区间」模型（refs 结构化）

### 14.1 权威 App 的真实实现（反编译确认）

| 环节 | 类 / 方法 |
|---|---|
| 注解内可点区间被点击 | `FootNoteAdapter$QuoteClickableSpan.onClick` → 取区间文本 + 书/章/节上下文 → `QuoteActivity` |
| 整段引用按「，」切分 | `QuoteFragment.setListView()` |
| 单段解析 | `ted.android.bibleread.tool.Quote.start()` |
| 区间查询 | `SQLHelper.searchRange()` |
| 「A 与 注N」 | `SQLHelper.searchRangeFootnote()` |
| 数据表 | `verse_all_final_gb_26`：`chapter_code`=书号(1–66)、`section_code`=章、`segment_code`=节、`unit_code`=0整/1上/2下 |

`Quote.start()` 的实际算法（不含文法层）：

1. 归一化：`至`→`～`、`并`/`比`→`與`（`R.string.and`）、`參見`/`該處`→`與`。
2. 特例：`首尾` → 10 条硬编码的诗篇查询；`見15b` → 查串珠表再递归解析；`标题` → 诗篇 `segment=0`。
3. 三个复合正则切 token（允许 `註?数字節?上?下?空白?～?`）。
4. 每 token：`clearString()` 去掉 `上/下/節/～/註/與/标题` → `MyTool.toNumber()` 中文数字逐位转整数 → 用 token 之前的文本匹配本章标题表决定是否换章，否则沿用当前章。
5. 拼 `CAST(chapter||section||segment AS INTEGER)`，`BETWEEN 起 AND 止` 直接取行。

**关键发现：`unit_code`（上/下）不参与区间计算**，仅书签模块使用。所以 App 里 `腓一19～21上` 会同时显示 21 上、21 下。精度来自数据（可点区间表 + 节/分段表），不是算法。

### 14.2 我们的落地设计

导出侧（`export_bible_sql_json.py`）：

- `_build_ref_ranges()` → 变长区间，`_encode_ranges()` 编码为单行字符串（缩进输出下体积最小）：
  - `[b,c,v]` 单节（`v=0` 整章）
  - `[b,c,v,u]` 单节 + 半节（`u=1` 上 / `2` 下）
  - `[b,c,v1,b2,c2,v2]` 区间（端点 `v=0` 表示章边界）
  - `[b1,c1,v1,u1,b2,c2,v2,u2]` 带半节修饰的区间
- 注解：`refs[].x = "49,1,10;49,3,9;54,1,4,2"`，`refs[].r` 保留为显示/复制串。
- 串珠：`bead.xr` 同编码；`bead.xrefs` 保留字符串。
- 源区间被截断（`v2<v1`，如「腓二5～1」）时不写 `x`，前端回退到引用串（与 App 的 BETWEEN 空结果一致）。

前端（`src/static/js/scripture-popup.js`）：

- 分片加载时收集 `CX_BIBLE_NOTE_RANGES` / `CX_BIBLE_XREF_RANGES` / `CX_BOOK_INDEX`。
- `buildVerseIndex()`：一次性把 `书+章:节+半节` 建成 `位置键 = 书*1e6 + 章*1e3 + 节` 的有序数组（31,295 行，排序后二分）。
- `expandRanges()`：对每条区间二分取边界，再按 `u` 裁剪边界节（**仅当该节存在更靠后的半节行时才裁剪**，避免未分节的整节被误删）。
- `renderVerseList(refs, ctx, ranges)`：有区间走区间检索，无区间走旧的 token 展开（向后兼容）。
- 注解 span 增加 `data-x`（紧凑串），点击时优先按区间打开；`data-refs` 仍作为标题与回退。
